# חנה ברגמן — מערכת גיוס והשמה

מערכת גיוס למתכנתות. אתר ציבורי שמזין את המאגר, ובק־אופיס שבו חנה מאתרת מועמדות
לפי דרישה ושולחת אליהן דיוור — הכל ממקום אחד.

**האפיון המלא:** [`docs/אפיון.md`](docs/אפיון.md)

---

## הרצה מקומית

```bash
npm install
cp .env.example .env.local   # ראי "הגדרות סביבה" למטה
npm run dev                  # http://localhost:3000
```

האתר עולה גם **בלי** Supabase — עמודי התוכן מוצגים כרגיל, והבק־אופיס רץ על
נתוני הדגמה כדי שאפשר יהיה לסקור את העיצוב ואת מנוע ההתאמה לפני שמחברים מסד
נתונים. טפסים שנשלחים במצב הזה נשמרים ל-`.local-submissions/` ולא נעלמים.

## הגדרות סביבה

| משתנה | חובה? | למה |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | לייצור | מסד נתונים, התחברות, אחסון קבצים |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | לייצור | — |
| `SUPABASE_SERVICE_ROLE_KEY` | לייצור | **שרת בלבד.** קליטת קו״ח ופניות מעסיקים עוברות דרכו כדי שזיהוי כפילויות וּולידציה ירוצו לפני כל כתיבה |
| `ANTHROPIC_API_KEY` | לניתוח קו״ח | חילוץ שדות מקבצי PDF / Word / צילום |
| `EMAIL_PROVIDER` | לדיוור | `smoove` \| `resend` \| `none` |
| `SMOOVE_API_KEY` / `RESEND_API_KEY` | לפי הספק | — |
| `NEXT_PUBLIC_SITE_URL` | לדיוור | בונה את קישור ההסרה מדיוור |

בלי `EMAIL_PROVIDER` הבחירה נשמרת אבל **מיילים לא יוצאים בפועל** — המערכת אומרת
את זה במפורש במסך הדיוור במקום להעמיד פנים ששלחה.

## הקמת Supabase

```bash
supabase link --project-ref <ref>
supabase db push          # מריץ את supabase/migrations/
```

אחר כך:

1. **Authentication → Providers** — להפעיל Email, ולהפעיל Google (מסך ההתחברות בעיצוב כולל "התחברות עם גוגל").
2. **Redirect URLs** — להוסיף `<site>/auth/callback`.
3. **להפוך את חנה למנהלת:**
   ```sql
   update app_users set is_admin = true where email = 'chana@...';
   ```
   בלי זה `/admin` חסום.

## שלוש החלטות שכדאי להכיר

### 1. זהות אחת למועמדת אחת

אותה בחורה מגיעה שלוש פעמים — מהדיסק, מרשימת סמוב, וכשהיא מעלה קו״ח מעודכן.
המערכת ממזגת לפי מייל, ואז לפי טלפון (שניהם מנורמלים), וזה נאכף בשני מקומות:
אינדקסים ייחודיים חלקיים במסד הנתונים, ופונקציה `find_candidate_match()` שרצה
לפני כל כתיבה.

**קו״ח לעולם לא נדרסים.** העלאה חדשה יוצרת גרסה נוספת ומעבירה את דגל
`is_current`. הקובץ המקורי נשמר תמיד.

בייבוא מסיבי, מיזוג ממלא רק שדות ריקים — מה שחנה הזינה ידנית לא נדרס אוטומטית.

### 2. מנוע ההתאמה הוא דטרמיניסטי, לא מודל

חנה מדביקה את טקסט הדרישה כפי שהמעסיק שלח. החילוץ מבוסס מילון עם אליאסים
(`נודג׳יאס` → `Node.js`) ולא קריאה למודל — כי הוא מיידי, חינם, עובד גם בלי
אינטרנט, ובעיקר **ניתן להסבר**: לכל מועמדת מוצגת שורה שאומרת מה התאים ומה חסר.

שני דברים שהיה קל לפספס והם מטופלים במפורש:

- `#` ו-`+` נחשבים חלק מהטוקן — אחרת השפה "C" נתפסת בתוך "C#" וכל קו״ח של C#
  נראה כמו קו״ח של C.
- תחיליות עבריות — "באזור **ה**מרכז" חייב להתאים לאזור "מרכז".

ניתוח **קבצי** קו״ח כן משתמש במודל (`src/lib/cv-parser.ts`): PDF וצילומים
נשלחים כבלוקים נייטיביים בלי OCR חיצוני, Word מחולץ לטקסט קודם. הפלט מוגבל
לסכימה עם רשימות הערכים המותרות, כדי שהסינונים ימשיכו לעבוד.

### 3. דיוור לפי חוק

לכל מייל מתווסף אוטומטית קישור הסרה, ו-`/unsubscribe` מכבד אותו מיידית בלי
התחברות — כנדרש בתיקון 40 לחוק התקשורת. רשימת הנמענות **נבדקת מחדש בשרת** לפני
שליחה; מה שהדפדפן שלח לא נסמך עליו.

## בונה קורות החיים והסריקה האוטומטית

- **סריקה בהעלאה** (`/submit-cv`): ברגע שמועמדת בוחרת קובץ, הוא נשלח ל-
  `/api/parse-cv`, השדות מתמלאים אוטומטית והיא רק מאשרת. הסריקה לעולם לא
  חוסמת — בלי `ANTHROPIC_API_KEY` (או כשהקובץ לא קריא) מוצגת הודעה והטופס
  ממולא ידנית, והקובץ עצמו נשלח כרגיל.
- **הקלטה קולית** (`/submit-cv`): "או ספרי לנו בקול" — זיהוי דיבור של הדפדפן
  (עברית) מתמלל בזמן אמת, התמלול עובר באותו מנוע חילוץ, השדות מתמלאים והיא רק
  מתקנת. ההקלטה מחליפה קובץ: התמלול נשמר במאגר כמסמך קו״ח לכל דבר (מגורסם,
  `extracted_text` מלא — נכנס לחיפוש החופשי). נתמך ב-Chrome / Edge / Safari;
  בדפדפן בלי תמיכה מוצג הסבר. אם החילוץ לא זמין — התמלול נשמר בשדה ההערות
  כדי שלא יאבד.
- **בונה קו״ח** (`/cv-builder`): טופס → שלוש תבניות (נקייה / קלאסית / כחולה) →
  תצוגה חיה בגודל A4 → הורדה כ-PDF דרך הדפסת הדפדפן. כל התבניות טור אחד,
  טקסט אמיתי — לפי כללי ה-ATS מהמאמר בבלוג.
- **תשלום על ההורדה**: מגדירים `CV_BUILDER_PRICE_ILS` + `PAYMENT_LINK` (עמוד
  תשלום מאוחסן — Grow/משולם/קארדקום). בלי הגדרה ההורדה חופשית.
  ⚠️ **כרגע השער הוא על בסיס הצהרה** ("שילמתי — להורדה") — אכיפה אמיתית
  דורשת webhook מספק הסליקה שינפיק אסימון הורדה חתום.

## מה עוד לא נעשה

- **אימות תשלום בבונה הקו״ח** — ראו לעיל; דורש בחירת ספק סליקה וחיבור webhook.
- **קליטת קו״ח ממייל נכנס** (`cv@`) — הסכימה מוכנה (`source = 'email'`), חסר
  ה-webhook.
- **הקלטה קולית כערוץ קליטה** — שלב 2 באפיון.
- **לינקדאין** — חנה אמרה במפורש "בואי נהיה יותר חכמים בעוד...".
- **המלצות אמיתיות** — `/testimonials` מכיל כרגע ציטוטים לדוגמה בלי שיוך.
  צריך להחליף בציטוטים אמיתיים עם שם ותפקיד לפני עלייה לאוויר.
- **תמונת ההירו** — כרגע איור SVG. להחלפה: `src/components/site/HeroImage.tsx`.
- **הלוגו** — קובץ המקור (`Group 105.svg`) הוא למעשה JPEG עטוף ב-SVG: רקע לבן אטום
  ומטשטש בהגדלה, כך שאי אפשר היה להשתמש בו על הפוטר הכהה. הסמל שורטט מחדש
  כוקטור אמיתי ב-`src/components/brand/Logo.tsx`. אם יש קובץ וקטורי מקורי
  מהמעצב — שווה להחליף.
- **הפונט** — האתר הקיים משתמש ב-Ping HL (מסחרי). כאן מוגדר
  `'Ping HL', 'Assistant'` — אם יש רישיון, זה פשוט יעבוד.
